# Лабораторная работа №2

## Потоковый анализатор файлов (`streamstats`)

---

## Описание проекта

В рамках лабораторной работы разработан Python-пакет **`streamstats`**, предназначенный для чтения файлов с событиями и формирования статистического отчёта в формате JSON.

Программа поддерживает два формата входных данных:

- **CSV** — таблица с заголовком и отдельной строкой для каждого события;
- **JSONL** — файл, в котором каждая строка содержит отдельный JSON-объект.

Интерфейс командной строки (**CLI**) реализован с помощью библиотеки **Typer**. Для проверки и преобразования данных события используется модель **Pydantic**. Входные файлы обрабатываются построчно, чтобы не загружать весь файл в память целиком.

## Формат события

Каждое событие должно содержать следующие поля:

| **Поле** | **Описание** |
|---|---|
| `timestamp` | Временная метка в формате ISO 8601. |
| `level` | Уровень события: `DEBUG`, `INFO`, `WARNING`, `ERROR` или `CRITICAL`. |
| `source` | Непустая строка, обозначающая источник события. |
| `message` | Текст сообщения. |

При чтении данных программа проверяет наличие обязательных полей и корректность их значений. Для CSV требуется заголовок с полями `timestamp`, `level`, `source`, `message`.

## Возможности программы

### Чтение входных файлов

Программа поддерживает CSV и JSONL. Файлы читаются построчно: каждая запись обрабатывается отдельно, без загрузки всего содержимого файла в память.

Можно передать несколько входных файлов одного выбранного формата. Их события объединяются для построения общего отчёта.

### Статистический отчёт

После обработки событий программа формирует JSON-отчёт со следующими данными:

- `total_events` — общее количество обработанных событий;
- `levels` — количество событий каждого уровня;
- `sources` — количество событий каждого источника;
- `top5_errors` — до пяти источников с наибольшим количеством событий уровня `ERROR` и `CRITICAL`;
- `first_timestamp` — самая ранняя временная метка;
- `last_timestamp` — самая поздняя временная метка;
- `skipped_lines` — количество пропущенных некорректных строк.

Если входных событий нет, временные метки в отчёте остаются пустыми (`null` в JSON).

### Обработка некорректных строк

По умолчанию программа прекращает обработку при обнаружении некорректной записи. Сообщение об ошибке содержит имя файла и номер строки, а CLI завершается с кодом `2`.

При использовании флага `--skip-invalid` некорректные строки пропускаются. Информация о пропусках записывается в лог на уровне `WARNING`, а их количество указывается в поле `skipped_lines` отчёта.

## Описание алгоритма решения задачи

### Алгоритм чтения CSV

1. Программа открывает CSV-файл.
2. Проверяет заголовок и читает строки по очереди.
3. Для каждой строки проверяет наличие обязательных данных.
4. Передаёт данные функции разбора события.
5. Если запись корректна, событие передаётся для дальнейшего анализа. Если запись некорректна, программа сообщает об ошибке или пропускает её в режиме `--skip-invalid`.

### Алгоритм чтения JSONL

1. Программа открывает JSONL-файл.
2. Читает файл построчно.
3. Преобразует каждую строку из JSON в структуру данных Python.
4. Проверяет обязательные поля и создаёт объект события.
5. Передаёт корректные события для дальнейшего анализа, а некорректные обрабатывает согласно выбранному режиму.

### Алгоритм анализа событий

1. Подсчитывается общее количество событий.
2. Для каждого уровня увеличивается соответствующий счётчик.
3. Для каждого источника подсчитывается количество событий.
4. Отдельно учитываются события уровней `ERROR` и `CRITICAL`, после чего определяется до пяти источников с наибольшим количеством таких событий.
5. Среди временных меток определяются минимальное и максимальное значения.
6. Все результаты объединяются в отчёт и записываются в JSON-файл.

## Принятые решения при реализации проекта

### 1. Разделение программы на модули

Программа разделена на файлы, каждый из которых отвечает за свою часть задачи.

| **Файл** | **Назначение** |
|---|---|
| `models.py` | Модель события и проверка его полей. |
| `parsers.py` | Чтение CSV и JSONL, разбор и проверка записей. |
| `analysis.py` | Подсчёт статистики по событиям. |
| `report.py` | Формирование итогового отчёта. |
| `errors.py` | Пользовательские классы исключений. |
| `__main__.py` | Настройка CLI и запуск программы. |
| `__init__.py` | Инициализация пакета `streamstats`. |

Такое разделение упрощает чтение кода, тестирование отдельных частей и поиск ошибок.

### 2. Использование Typer

Библиотека **Typer** используется для создания команды `analyze` и обработки аргументов командной строки. Пользователь может указать входные файлы, формат данных, путь для отчёта и режим обработки некорректных строк.

### 3. Построчная обработка файлов

Вместо чтения всего содержимого файла сразу программа обрабатывает записи по очереди. Это позволяет ограничить потребление памяти и подходит для работы с большими файлами.

### 4. Использование Pydantic для модели события

Модель `Event` описывает структуру события и проверяет типы и допустимые значения полей. Это позволяет сосредоточить правила проверки данных в одном месте, а не повторять их во всех парсерах.

### 5. Использование генераторов

Функции чтения могут передавать события по одному с помощью `yield`. Благодаря этому записи можно обрабатывать последовательно, не создавая дополнительный список всех событий на этапе чтения конкретного файла.

### 6. Отдельные классы исключений

Для различных ошибок используются отдельные типы исключений: ошибка неподдерживаемого формата, ошибка события и ошибка временной метки. Это помогает отличать причины ошибки и выводить более понятные сообщения.

### 7. Режим пропуска некорректных строк

Флаг `--skip-invalid` позволяет продолжить обработку файла, если отдельные строки содержат ошибки. Количество пропущенных строк учитывается отдельно и включается в итоговый отчёт.

### 8. Автоматическое тестирование

Для проверки проекта используются тесты **pytest**. Они проверяют чтение CSV и JSONL, обработку пустых файлов, поведение при некорректных строках, обработку нескольких файлов и работу CLI.

## Примеры запуска программы

### Анализ CSV

```bash
python -m streamstats analyze valid.csv --format csv --output report.json
```

Команда читает файл `valid.csv` и сохраняет статистический отчёт в `report.json`.

### Анализ JSONL

```bash
python -m streamstats analyze valid.jsonl --format jsonl --output report.json
```

### Объединение нескольких файлов

```bash
python -m streamstats analyze valid.csv second.csv --format csv --output report.json
```

В отчёт включается статистика по событиям из обоих файлов.

### Пропуск некорректных строк

```bash
python -m streamstats analyze invalid.jsonl --format jsonl --skip-invalid --output report.json
```

Некорректные строки пропускаются, а их количество включается в поле `skipped_lines` отчёта.

### Справка по программе

```bash
python -m streamstats --help
```

Чтобы узнать доступные параметры команды анализа, используйте:

```bash
python -m streamstats analyze --help
```
